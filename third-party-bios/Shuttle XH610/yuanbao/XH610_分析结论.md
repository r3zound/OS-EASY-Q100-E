## 二、微码分析（关键结论）

### ✅ 14 代微码齐全（且是 2024-2025 最新版）

虽然原始微码块的字节扫描因 **LZMA 压缩 + 字节对齐** 未直接列出条目，但：

1. **平台明确声明支持 RPL-S（Raptor Lake-S = 13/14代）**
2. **微码 revision 分布非常健康**：

| 微码 rev | 出现次数 | 含义 |
|---|---|---|
| **`0x12B` (299)** | 25 次 | ✅ **Intel 14代稳定性终极修复（0x12B）** |
| **`0x11D`** | 18 次 | ✅ 14代中期修复版 |
| `0x30` | 191 次 | 12代常见 rev |
| `0x2C` | 112 次 | 12代常见 rev |

> **`0x12B` 出现 25 次** = 这份 BIOS 含有 **Intel 为修复 13/14 代"电压漂移/缩肛"发布的 0x12B 微码**，且覆盖多个签名。**这正是你上一轮那张图里 `000B0671 / rev 0x12B / 2024-08-29` 的同一份微码。**

✅ **结论：这份 XH610 BIOS 完整支持 i5-14400（14代），微码版本比噢易云 65F001HE 还新。**

## 三、值得提取的东西（核心：Setup 变量 + 微码）

这份 BIOS 最大的价值 **不是"整包刷"（绝对不能跨板刷）**，而是它**比噢易云定制 BIOS 开放得多**——**Setup 变量表完整**：

| 可提取项 | 在这份 BIOS 里 | 在噢易云 JHS65F 里 |
|---|---|---|
| `CpuSetup`（CPU 设置，含 HT）| ✅ 存在 | 大概率精简/隐藏 |
| `SaSetup`（系统代理）| ✅ 存在 | 精简 |
| `PchSetup`（PCH）| ✅ 存在 | 精简 |
| **`OverClocking`（超频菜单）** | ✅ **存在** | ❌ 通常无 |
| **`PL1` / `PL2`** | ✅ **存在** | ⚠️ 部分 |
| **`ICC`（电流/功耗）** | ✅ **存在** | ⚠️ 部分 |
| 微码（含 0x12B）| ✅ 完整 | 需核实 |

### 🎯 真正"值得提取"的两条

**1. 微码块（含 0x12B）—— 可直接用于补充噢易云 BIOS**
若你的 JHS65F 缺 14 代微码，可**只提取微码卷**，用 MMTOOL 注入到噢易云 BIOS 中（比整包移植安全得多）。

**2. Setup 默认值（解锁 PL/ICC/HT 的正确姿势）**
噢易云那份"改版 BIOS"是靠**手工改 NVRAM 默认值**实现"关 HT / 解锁 PL4 / ICC"。而 **Shuttle 这份 BIOS 原生就有完整的 `OverClocking / PL1 / PL2 / ICC` Setup 项**——说明 **Shuttle 的 BIOS 对这些选项是"菜单可见 + 可配置"的**，参考价值极高。

## 四、⚠️ 绝对不能做的事：跨板整包刷

**这份 XH610 BIOS 绝对不能直接刷到噢易云 JHS65F 主板上！** 原因：

1. **厂商不同**：Shuttle vs 噢易云 —— EC（嵌入式控制器）、Super I/O（Shuttle 用 ITE、噢易云也是 ITE IT8613 但型号/配置不同）、GPIO 定义完全不同
2. **板载设备不同**：网口、声卡、USB 口映射、VGA/HDMI 配置不同 —— 刷错会**外设全失灵**
3. **EC / ME 区域不匹配** —— 可能**变砖且无救**

> 📌 **正确的跨板复用方式是"模块化提取"**：只取 **微码（CPU 支持）**，最多参考 **Setup 选项的 VarStore 结构**，绝不整包替换。

## 五、给你的行动建议（优先级排序）

### ✅ 第一优先：核实你当前 BIOS 是否真缺 14 代微码
在你 **JHS65F 官方 BIOS（65F001HE）** 上跑 MCExtractor：
- 若**已含 `0x00B067`** → **不用折腾，直接换 i5-14400 即可点亮**（这是最理想情况）
- 若**确实缺失** → 走第二步

### ✅ 第二优先：只移植微码（安全做法）
1. 用 **MCExtractor** 从 `XH610000.211.bin` 提取出 14 代微码 `.bin`（含 0x12B）
2. 用 **MMTOOL** 打开噢易云官方 BIOS → 定位微码卷 → **插入/替换** 14 代微码
3. 刷回 JHS65F，**保留原版 EC / ME / Setup**，仅补 CPU 支持 —— **风险可控**

### ⚠️ 不建议：直接套用 Shuttle 的 Setup 默认值
Shuttle 的 `OverClocking/PL` 菜单项**变量 ID 和噢易云不同**，直接照搬改 NVRAM 容易改错位置。**若要解锁功耗，建议在噢易云 BIOS 上用 AMIBCP 逐个对照 `CpuSetup` 改。**
